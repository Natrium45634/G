# Архитектура

## 1. Технологический стек и почему он

| Решение | Обоснование |
|---|---|
| **Go 1.26** | Один статический исполняемый файл без зависимостей; кросс-компиляция под Windows из любой ОС; встроенные тесты и профилировщик; предсказуемая производительность без сборщика-«тормоза» на таком объёме; простой детерминированный код. |
| **Ebitengine v2.10** (2D) | Зрелый 2D-движок на Go. На Windows работает через DirectX без cgo — `.exe` собирается кросс-компиляцией и запускается двойным кликом. Векторная графика и TTF-текст «из коробки». |
| **JSON + `go:embed`** | Определения хранятся в данных и встраиваются в файл игры; при наличии папки `data/` рядом с игрой берутся из неё (модификации). |
| Шрифты Go (Bigelow & Holmes) | Встроены, поддерживают кириллицу. |

Ограничение технологии, о котором стоит знать заранее: Ebitengine — 2D. Для перехода
на 3D-представление ядро (`engine/*`) переносится без изменений (оно не зависит от
графики), переписывается только `ui/`.

## 2. Модули и зависимости

```
                ┌──────────── cmd/hextactics ─────────────┐
                │                                          │
                ▼                                          ▼
               ui  ──(только чтение мира + sim.Command)──► sim
                                                         │  │  │
                     ┌─────────────┬─────────────┬───────┘  │  └──────────┐
                     ▼             ▼             ▼          ▼             ▼
                  combat        gamemap        data       stats          rng
                     │             │             │          ▲
                     ├──► hex ◄────┘             └──────────┘
                     └──► data, rng
```

Зависимости направлены строго вниз, циклов нет (их запрещает компилятор Go).

| Модуль | Ответственность (по разделу 13 ТЗ) |
|---|---|
| `engine/hex` | координаты (q, r, s=−q−r), шесть соседей, расстояние `(|dq|+|dr|+|ds|)/2`, направления и угловые проверки в целых числах, области (радиус, кольцо, линия, конус, дуга), линия между клетками, пиксели (только для UI). |
| `engine/gamemap` | клетки (ID, поверхность, высота, укрытие, биом, элементы), проходимость по классам юнитов, стоимость шага, обрывы, двери, Dijkstra (область доступности), A* (маршрут), поиск до любой подходящей клетки, линия видимости с частичными препятствиями. |
| `engine/stats` | определения характеристик, блок значений экземпляра, модификаторы (плоские, %, множители; постоянные, временные, ситуативные), порядок расчёта и объяснение. |
| `engine/combat` | секторы, неожиданность, попадание, уклонение, блок, крит, урон (броня × позиционная защита, сопротивление, уязвимость, иммунитет, блок), прогноз шансов без бросков. |
| `engine/data` | структуры определений, загрузка JSON со строгой проверкой полей и перекрёстных ссылок, встроенный набор данных. |
| `engine/rng` | SplitMix64 с сериализуемым состоянием. |
| `engine/sim` | время и часы, мир и юниты, ОД и ресурсы, приказы и очередь, проекция очереди (стоимость/предупреждения до исполнения), исполнение и политики ошибок, умения (цели, области, рывок, каналирование), эффекты, ауры, объекты (ловушки, отложенные удары), призыв, видимость, события и пассивные навыки, ИИ, команды, сохранение. |
| `ui` | выделение, подсветка, маршруты, очередь, предпросмотр, панели, журнал, визуальные эффекты. |

**Интерфейс не меняет мир напрямую.** Все изменения проходят через `World.Apply(Command)`
(игрок) или внутренний `apply` (ИИ — тот же путь проверки). Клик не меняет здоровье,
координаты или ОД; он создаёт команду «поставить приказ в очередь».

## 3. Время

* **Реальное время** — секунды кадров (`Clock.RealElapsed`).
* **Игровое время** — `тик / ticks_per_second` (по умолчанию 20 тиков в секунду). На паузе не растёт.
* **Время симуляции** — номер тика `World.Tick`.
* **Длительность действия** — в тиках (`Action.Start..End`), задаётся в данных в секундах.

`Clock.Advance(dt)` накапливает `dt × скорость` и исполняет **целые фиксированные тики**.
При 1× и 4× исполняются одни и те же тики в одном и том же порядке — меняется только
их число за кадр, поэтому результат не зависит ни от FPS, ни от скорости
(тесты `TestScenarioE_SpeedIndependence`, `TestFrameRateIndependence`). Если компьютер не
успевает, игровое время замедляется, но тики не пропускаются. Автопауза проверяется
после **каждого** тика, поэтому игра останавливается ровно на тике события при любой
скорости (`TestAutoPauseStopsExactlyAtEventTick`).

### Порядок шага симуляции (`World.Step`)

1. тик++; модель ОД «цикл» (если выбрана) восстанавливает ОД в начале цикла;
2. ИИ (раз в `ai_think_seconds`) — выдаёт команды бездействующим юнитам;
3. регенерация (ОД, ресурсы, HP) и эффекты (длительность, периодические действия, ауры) — по возрастанию ID юнита;
4. действия и приказы — по возрастанию ID юнита;
5. объекты мира (таймеры, срок жизни);
6. видимость (раз в `vision_update_ticks` или при изменениях);
7. рассылка новых событий пассивным навыкам (FIFO, включая порождённые реакциями, с ограничением на тик);
8. проверка исхода боя.

## 4. Юниты, ОД, состояние и приказ

* Юнит (`sim.Unit`) — экземпляр: ID, класс (ссылка на определение), позиция, ориентация,
  HP, ОД, ресурсы, эффекты, перезарядки, очередь, текущий приказ, текущее действие.
  Разные юниты используют одно определение класса и хранят свои текущие параметры.
* ОД хранятся целыми **милли-ОД** (1 ОД = 1000). Дробная регенерация копится без ошибки округления.
* **Состояние юнита** (`State`: бездействие, движение, поворот, подготовка, восстановление,
  каналирование, ожидание, защита, оглушён, спит, погиб) вычисляется из текущего действия
  и эффектов и отделено от **приказа** (`Order`).
* **Действие** (`Action`) — атомарная единица времени: шаг на клетку, поворот, подготовка
  умения, восстановление, каналирование, ожидание, взаимодействие. Два несовместимых
  действия одновременно невозможны: у юнита одно текущее действие.

### Жизненный цикл приказа

`planned → active → (waiting ↔ active) → done | failed | interrupted | skipped | cancelled`.

Для каждого типа определены условия начала/продолжения/завершения и расход ресурсов
(`engine/sim/exec.go`). Все условия проверяются **в момент исполнения** по текущему миру:

| Приказ | Исполнение |
|---|---|
| Move | путь A* строится при старте; перед каждым шагом проверяется следующая клетка (занятость, проходимость, двери, обрыв), ОД; шаг оплачивается при начале; позиция переключается в середине шага. |
| Turn | стоимость = число шагов по 60° × `turn_cost`; длительность = шаги × `turn_time`. |
| Attack / Skill | цель → (подход по шагам, если вне дальности/видимости) → разворот (если цель вне сектора атаки) → перезарядка/ресурсы/ОД (ожидание) → оплата → подготовка → **повторная проверка цели** → применение → восстановление/каналирование. |
| Guard | защитная стойка на время; с реакцией — при входе видимого врага в зону обычной атаки (и в сектор) превращается в атаку. |
| Wait, Interact, Stop | ожидание; подход к двери/рычагу и переключение; конец очереди. |

### Политики ошибок

У каждого приказа есть политика (`skip` по умолчанию, у движения — `repath`):
* `abort` — прервать всю очередь;
* `skip` — пропустить приказ и продолжить;
* `repath` — перестроить путь; если невозможно — ждать до `wait_timeout`, затем пропустить;
* `wait` — ждать выполнения условий до `wait_timeout`, затем пропустить.

Условия, которые разрешатся сами (нехватка ОД, ресурса, перезарядка, оглушение,
обездвиживание), всегда приводят к ожиданию (`waiting`) — это и есть «гибкая очередь,
исполняемая по мере восстановления ОД».

### Проекция очереди

`World.ProjectPlan(unit)` — моделирование очереди без бросков: позиция и ориентация до и
после каждого приказа, путь (включая подход к цели), стоимость движения/поворота/действия,
нарастающий итог, ресурсы, область умения, ошибки и предупреждения (союзник в области,
перезарядка, нет пути сейчас из-за юнитов и т.п.). Её используют:
* интерфейс — линии, номера, маркеры, «итого / после очереди», «не хватает N ОД → ожидание»;
* команда постановки приказа — отказ при ошибке и **строгое резервирование** (режим `strict`:
  сумма очереди не может превышать текущие ОД).

Тяжёлая часть (поиск путей) кэшируется по версии очереди, версии карты и версии занятости —
пересчёт не идёт каждый кадр и не пересчитываются все маршруты при каждом изменении клетки.

## 5. Бой

Сектор: `f` — взгляд цели, `a` — направление от цели на атакующего, `Δ = min(|f−a|, 6−|f−a|)`.
Направления сравниваются **целыми скалярными произведениями** (без float), ничья (ровно
между двумя направлениями) трактуется в пользу защищающегося.

Порядок разрешения атаки (`combat.Resolve`), каждый пункт — отдельный бросок:
1. **Обнаружение (неожиданность)**: профиль сектора (0/30/70/100%) + скрытность атакующего − бдительность цели + «атакующий не виден стороне цели» + «цель связана боем». Оглушённая или спящая цель — 100%.
2. **Попадание**: точность + модификатор умения + высота × бонус − укрытие цели (дальние атаки) − частичные препятствия на линии; ограничение [hit_min, hit_max].
3. **Уклонение**: уклонение цели × коэффициент сектора; при неожиданной атаке не применяется.
4. **Блок/парирование**: блок цели × эффективность фронтального блока; при неожиданной атаке не применяется.
5. **Крит**: шанс атакующего (+ настраиваемый бонус неожиданности; это бонус, а не автокрит).
6. **Урон**: база + характеристика × коэффициент → разброс → крит → броня × позиционная защита сектора → сопротивление → уязвимость → иммунитет → блок → округление (минимум 1). Затем в `sim`: поглощение (барьеры) → перенаправление (защитник) → HP → снятие сна → прерывание → отражение → смерть.
7. **Дополнительные эффекты**: шанс операции → сопротивление эффекту / иммунитет → сокращение длительности (упорство).
8. **Прерывание**: урон прерывает подготовку/каналирование умений с флагом `interruptible`.

Каждая атака пишет в журнал строку и **полное объяснение расчёта** (броски и модификаторы).
Подсказка игроку (`AttackPreview`) считает те же шансы без бросков и не раскрывает скрытые
характеристики (сопротивления врага открываются после удара соответствующим типом урона).

## 6. Характеристики

Перечень не зашит в код — он в `stats.json`. Порядок расчёта (`stats.Block.compute`):

```
база → постоянные плоские → постоянные % (сумма) → постоянные множители
     → временные/ситуативные плоские → временные/ситуативные % → множители → ограничения
```

`Explain()` возвращает каждый шаг с источником (класс, пассивный навык, эффект).
Ситуативные модификаторы имеют условие (`when`: роль, сектор, местность, тип атаки, порог HP)
и учитываются только при запросе с контекстом (например, «Удар в спину» — только при атаке
с дальнего фланга или тыла). Безусловные значения кэшируются; кэш сбрасывается при смене
набора эффектов — характеристики не пересчитываются каждый кадр.

Сопротивление урону, уязвимость, иммунитет к урону (тег), сопротивление эффекту (шанс),
иммунитет к эффекту (тег), сокращение длительности (упорство), поглощение (пул эффекта),
отражение (характеристика) и перенаправление (эффект с источником) — разные механизмы,
не сводятся к одному коэффициенту.

## 7. Умения

Умение собирается из данных: цель (`self | unit | hex | direction | auto`), фильтр целей,
дальность, линия видимости, форма (`single | line | cone | radius | arc | self`), кого
задевает, нужен ли поворот, бросок попадания, тип атаки, подготовка, восстановление,
перезарядка, ресурсы, прерываемость, «опасность» (для автопаузы), рывок по маршруту,
каналирование, и список **операций**: `damage`, `heal`, `apply_effect`, `remove_effect`,
`restore`, `place_object` (ловушки, отложенные удары), `summon`.
Новое умение из существующих частей добавляется без изменения ядра (тест сценария F).

## 8. События и пассивные навыки

Все изменения порождают события (`sim.Event`) с возрастающим номером. События:
* пишутся в журнал (если есть текст и они видимы стороне игрока);
* проверяются часами для автопаузы;
* рассылаются пассивным навыкам (`blocked`, `evaded`, `damaged`, `hit_dealt`, `ally_died`, `killed`)
  через общий механизм с шансом, перезарядкой, одноразовостью и порогом HP.

## 9. Видимость и ИИ

Сторона видит врага, если хотя бы один её юнит видит клетку (дальность обзора + линия
видимости). Невидимые враги не показываются и не могут быть выбраны целью; атака
невидимым противником получает бонус неожиданности. ИИ думает только за бездействующих
юнитов и выдаёт обычные команды — для него действуют те же правила.

## 10. Сохранение и детерминизм

`World.Save/Load` сериализует: тик, состояние ГСЧ, юнитов (включая очереди, текущие
действия, эффекты, перезарядки, ресурсы), объекты, изменения карты (двери, поверхность),
знания сторон, часы и настройки автопаузы. Тест `TestSaveLoadContinuesIdentically`
проверяет, что после загрузки симуляция продолжается бит-в-бит.
`World.CommandLog` — журнал внешних команд с номером тика: по нему бой воспроизводится
полностью (`TestReplayFromCommandLog`).

## 11. Интерфейс

`ui/battle.go` — режимы ввода и команды; `ui/panels.go` — панели и кнопки (пересоздаются
каждый кадр из состояния мира); `ui/render_map.go`, `ui/render_units.go` — карта, юниты,
планы, предпросмотры; `ui/vfx.go` — визуальные эффекты, построенные **только на событиях**.
Слой местности кэшируется в текстуре и перерисовывается при смене масштаба или версии карты.
