# Решения по открытым вопросам и трактовки ТЗ

ТЗ просит для первой версии выбрать по одному основному правилу на механику, оставив
альтернативы настраиваемыми. Все настройки ниже — в `engine/data/content/rules.json`.

## Раздел «Решения, которые нужно уточнить»

| Вопрос | Решение первой версии | Альтернатива (настройка) |
|---|---|---|
| ОД восстанавливаются непрерывно или в начале цикла? | **Непрерывно** в игровом времени (`ap_regen` ОД/с у каждого класса). Естественно для реального времени с паузой. | `"ap_model": "cycle"` + `"cycle_seconds"` — полное восстановление в начале тактического цикла. Обе модели реализованы и покрыты тестом. |
| Поворот всегда стоит ОД? | **Явный поворот всегда стоит ОД** за каждые 60° (`turn_cost`). Поворот по направлению шага при обычном движении входит в стоимость шага. | `"turn_free_while_moving": false` — поворот при движении тоже оплачивается. |
| Прерывать ли движение при обнаружении врага, уроне, угрозе? | Движение **не прерывается** (иначе очереди становятся непредсказуемыми). Урон **прерывает подготовку и каналирование** умений с флагом `interruptible`. Оглушение/сон прерывают любое текущее действие. Обнаружение врага и опасные атаки вызывают **автопаузу** (решение принимает игрок). | `"interrupt_on_damage"`; набор событий автопаузы — в интерфейсе. |
| Атака фиксируется на цели или на гексе/направлении? | Зависит от умения (`targeting` в данных): обычная атака и одиночные умения — **на цели** (юнит отслеживается, при уходе из зоны во время замаха удар не достигает цели); площадные — **на гексе**; линия, конус, дуга, натиск — **на направлении**; «Быстрый выстрел» — **автовыбор** цели при исполнении. | `targeting` у каждого умения. |
| Юниты исполняют только приказы или действуют автономно? | Юниты игрока **исполняют только приказы**. Автономные реакции — только через явный приказ «Защита» с реакцией (стойка + атака по врагу, вошедшему в зону). Противник управляется ИИ, который выдаёт обычные приказы. | Сторона может быть переключена на ИИ (`controller` в сценарии). |
| Разрешена ли атака во время движения? | **Нет** в первой версии: у юнита одно действие. «Умение по маршруту» реализовано как рывок + удар (Натиск). | Поле для параллельных действий (стрельба на ходу) — в плане. |

## Прочие трактовки

* **Резервирование ОД.** Сумма стоимости очереди показывается как «резерв». Режим `flexible`
  (по умолчанию) разрешает очередь дороже текущих ОД — приказ ждёт восстановления
  (статус команды «ожидает условий»). Режим `strict` отклоняет такую команду с кодом
  `INSUFFICIENT_ACTION_POINTS`. Переключается клавишей `P` или кнопкой «ОД: …».
* **Защита от обхода стоимости частыми мелкими приказами.** ОД списываются в момент начала
  действия, отмена не возвращает ОД, стоимость поворота линейна по числу шагов
  (три поворота по 60° стоят ровно как один на 180°), шаг движения оплачивается целиком.
  Покрыто тестами `TestTurnCostsAPAndNoSplitExploit`, `TestCancelDoesNotRefund`.
* **Сектор при равноудалённости.** Если угроза лежит ровно между двумя направлениями,
  выбирается сектор, более благоприятный для защищающегося. Альтернатива (менее
  благоприятный) — одна строка в `combat.SectorOf`.
* **Атака и сектор атакующего.** Для обычной атаки цель должна быть в секторе атаки
  атакующего (`attack_arc_max_delta = 1`: фронт и ближние фланги); иначе выполняется
  автоматический разворот за ОД (`auto_turn_to_attack`). Для направленных умений нужна
  точная ориентация.
* **Неожиданность.** Классифицирует атаку; не даёт автопопадания. При неожиданной атаке
  не применяются активные защиты (уклонение, блок — настраиваемо) и добавляется
  настраиваемый бонус к шансу крита (+10, не автокрит).
* **Детерминизм между платформами.** ОД, HP, время и шансы — целые числа. Характеристики
  считаются в float64 с фиксированным порядком операций и округляются на границах
  (шансы, урон). На одной платформе результат бит-в-бит; между архитектурами возможны
  расхождения только в пограничных случаях округления — при необходимости сетевой игры
  характеристики переводятся на фиксированную точку (план).
* **Обзор и ориентация.** В первой версии обзор круговой (дальность + линия видимости);
  ориентация влияет на обнаружение атаки, уклонение, блок и броню. Фронтальный обзор,
  периферийное зрение, шум и слух — следующий этап (архитектура готова: видимость
  считается в одном месте `engine/sim/vision.go`).
* **Перенаправление урона.** Реализовано эффектом «Под защитой»: часть урона получает
  источник эффекта, если он рядом.
